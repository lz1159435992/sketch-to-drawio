# 复杂插画/场景处理（A′→B′→C′→D′→E 阶梯）

SKILL.md 插画阶梯的展开。核心原则：**风格一致性优先于语义匹配**——生动感来自构图与层次，不来自外来画风。只有 A′–D′ 全部不可用时才回退到保底（E → C 通用形状）。

第二条原则：**忠实原图优先于重新构图**——用图标集元素"重新构图"一个场景是混乱感的主要来源；原草图已有清晰插画时，优先裁剪矢量化（B′）或裁剪高清化（C′），而不是另起炉灶重新拼场景。

## 判定：什么时候算"复杂插画"

- 多元素场景（风景、城市、实验装置、人物互动）；
- 装饰性/氛围性图形，无单一功能语义；
- 草图中明显是"一张小插画"而非"一个图标"（多色、有遮挡关系、面积较大）。

单一功能语义的图形（车、文件、盾）仍走简单图标 A→B→C，不要升维到插画阶梯。

## 风格一致性硬约束（任何路径都必须满足，任一不满足即降级）

1. **描边宽度族一致**：插画元素的描边粗细与全图图标属于同一族（如 Lucide 2px 族）；
2. **颜色取自图内色板**：只允许使用全图既有低饱和色板中的颜色（前后景分层可用 2–3 色）；
3. **无渐变**：除非全图本身使用渐变，否则插画不得含渐变填充；
4. **无自带背景/地平线**：元素必须是透明底、无自带地平线或天空方块，否则组合时出现多条地平线；
5. **基线与视角一致**：组合元素共享同一地平线与视角（正面/侧面/俯视不混用）。

## A′. 同集组合插画（首选，有质量门槛）

用与全图**同一图标集**的多个元素 + z-order 遮挡构图：

- 例：山路场景 = Lucide `mountain-snow`（后，浅灰蓝）+ `tree-pine`×2（两侧，图内绿）+ `route`（前，深蓝）。
- 后景元素在 XML 中先写（drawio 文档序即 z 序）；元素允许轻微重叠以制造遮挡层次。
- 颜色通过 `currentColor` 替换实现（同简单图标），前后景用色板内的深浅色分层。
- 描边宽度、圆角、端点与全图其他图标天然一致——这是它排在首选的原因。

**质量门槛**（防止越拼越乱）：

- 元素 ≤3 个、大小层级清晰（一主两从）、重叠克制；
- 导出目标尺寸下目检仍显混乱时，**最多修订一轮**（减元素/调层级）即降级到 B′，不反复打磨；
- 多元素复杂场景（>3 个组成部分）直接跳过 A′，从 B′ 开始。

## B′. 原图裁剪 + 彩色描摹（"裁剪高清化"的矢量版，A′ 不通过时首选）

忠实于用户草图自身的插画内容，不虚构。保持全矢量输出：

```bash
magick sketch.png -crop <w>x<h>+<x>+<y> +repage <id>-raw.png
magick <id>-raw.png -resize 300% -despeckle <id>-clean.png
vtracer --input <id>-clean.png --output <id>-trace.svg \
    --colormode color --mode polygon --color_precision 6 --filter_speckle 4
python3 <skill-dir>/scripts/remap_svg_colors.py <id>-trace.svg -o <id>-color.svg \
    --palette "<图内色板>"
```

- 只裁插画区域，**不要把草图文字裁进去**（文字一律用 drawio 原生文本重排）；
- `--color_precision` 控制颜色数（扁平风插画 5–7 合适；过高会把抗锯齿噪点变成碎色块）；
- 描摹后**先色板映射再目检**：色块错位、细节糊化任一明显就放弃，降 C′；
- 通过则作为独立 SVG 对象插入（不栅格化、不嵌整张草图），attribution 记 `traced_from_user_sketch` / `inserted_svg`；
- vtracer 缺失且 Inkscape 多色描摹不可用时直接降 C′，不要退化成黑白描摹（失去表现力）。

## C′. 原图裁剪 + 栅格高清化（装饰补丁允许栅格）

描摹失真明显（细节丰富的写实插画、照片感场景）时的务实路径：保留原图像素，只做高清化处理。

```bash
python3 <skill-dir>/scripts/embed_raster.py sketch.png \
    --crop <x>,<y>,<w>,<h> --scale 3 --denoise --sharpen \
    --bg-flatten-white 14 \
    --svg-out <id>-raster.svg --print-uri > <id>-uri.txt
```

- 输出 percent-encoded data URI，直接作为 drawio 单元 `image=` 值插入（本环境实测唯一可靠的栅格嵌入路径；详见 `icon-sourcing.md` 嵌入矩阵）；
- 护栏：
  - **只裁插画不裁文字**——裁入文字在论文图中不可编辑、不可翻译，属缺陷；
  - 分辨率按**显示尺寸 ×2–3** 准备（如显示 120×90px，则裁剪放大后 ≥240×180px），避免放大后像素化；
  - 背景处理三选一（实测结论）：**`--bg-flatten-white TOL` 为浅蓝/浅灰底草图的首选**（从四角泛洪、只改背景连通区为纯白不透明，保住云朵/雪顶/虚线等封闭白色细节，且与白底单元格无缝衔接）；`--bg-remove-white`（全局近白透明化）会咬掉插画内部的白色元素、留下毛边，仅用于纯白底且无白色细节的草图；保留原底会在白底单元格上留下可见的浅色卡边，仅当单元格底色与草图底色一致时可用；
  - 栅格补丁只作装饰性视觉锚点，每张图 ≤1 处；承载语义的元素仍须矢量；
- attribution 记 `cropped_from_user_sketch`，并注明裁剪区域坐标与处理参数；
- QC 必查：放大后是否像素化/模糊、去白是否产生光晕、与周围矢量元素的边缘衔接是否突兀。

## D′. 色板映射彩色集 / 原生形状组合（B′/C′ 均不可用时）

**D′-1 色板映射彩色集**：

1. **选集**：只用扁平几何、无渐变、无自带背景的彩色集（如 `flat-color-icons` 类）；**渐变系贴纸风 emoji 集（fluent-emoji、noto、twemoji、openmoji 彩色）在线性学术图中是反模式**——实测与 Lucide 类线性图标并置会互相破坏（渐变 vs 描边是渲染体系冲突，非饱和度问题），仅当全图本身是彩色扁平风时才可用。
2. **色板映射**：把彩色 SVG 的颜色量化后映射到图内色板：
   ```bash
   python3 <skill-dir>/scripts/remap_svg_colors.py in.svg -o out.svg --palette "#8AA5BE,#39739D,#3F7E5A"
   ```
   映射按亮度保秩（最亮→最亮色板色……），保留明暗结构；映射后必须目检。
3. CC-BY 类集合必须署名并进 attribution（见许可表）。

**D′-2 原生形状组合**：

用 drawio 基础形状拼简化场景：山=`triangle` 叠加（后深前浅）；树=`ellipse`+小 `rectangle`；路=粗灰曲线；云=`cloud`；建筑=矩形组合。颜色取图内色板。工作量高，只在插画对语义重要（而非纯装饰）时值得；纯装饰插画宁可直接降 E。

## E. 保底

单色线性图标组合（如 Lucide `route`+`cloud-sun`）表达场景关键词；再不行降 C 通用形状 + 文字标签。保底也要记 attribution 与 QC。

## 许可速查

| 集合 | 风格 | 许可证 | 署名 | 适用 |
|---|---|---|---|---|
| 与全图同集（如 lucide） | 线性单色 | 同全图 | 无 | A′ 首选 |
| 用户草图裁剪 | 原图（矢量描摹或栅格） | 用户自有 | 无 | B′/C′ |
| `flat-color-icons` | 扁平彩色 | MIT | 无 | D′-1 |
| `game-icons` | 单色细节丰富 | CC-BY-3.0 | 必须 | D′-1 单色场景 |
| `fluent-emoji`/`noto`/`twemoji`/`openmoji` | 渐变贴纸风 | MIT/Apache/CC-BY | 视集合 | **反模式**（线性学术图） |

## 记录要求

- 每个插画元素在 attribution 中单独一行：库/名称、许可证、署名要求、`open_source` / `traced_from_user_sketch` / `cropped_from_user_sketch` / `redrawn_native`；
- CC-BY 元素必须在论文适当位置署名——在 QC 待确认清单提醒用户（`license_attribution` 类型）；
- QC 自检表必查"插画风格一致性"（硬约束 5 条，C′ 栅格补丁豁免描边族要求）与"保真度"（描摹失真、色块错位、栅格像素化/光晕）。
